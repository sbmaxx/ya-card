# Windows compile measurements

Starting point: `da7c6fa` (`uLoopCounts` already present). Work is local, on
`windows-compile`; no deployment or server changes. The owner accepted a
5–10 s checkpoint, followed by further attempts towards the original ~2 s goal.

## Checkpoint: share the tint jobs

Four static `tinted()` calls cloned the studio lighting into the body, wordmark,
first letter and name. A uniform-bounded four-job loop now calls it once. Each
job retains its original predicate, input material and arithmetic. Body/link
colour, the first-letter blend, occlusion and the final mute remain separate.
No light, sample, tap or parallax count was reduced. Other edition processes
remain generated by the existing `letteringCode()`.

| Clean-profile run | Light compile | Dark compile |
| --- | ---: | ---: |
| Baseline, uniform loop counts | 18.647 s | 16.574 s |
| Shared tint jobs | 5.675 s | 8.820 s |

Times are `card:compiled - card:create`, not total page readiness. The card
program's link-to-observed-ready intervals differ by less than 2 ms. The baseline
light repeat was 18.865 s. This repeat has the historical artifact label
`diffuse-light-01`: the intended edit did not apply, and the unchanged shader and
frame hashes confirm it was another baseline run.

### GPU time

`EXT_disjoint_timer_query_webgl2`, main-resolution `drawCard` only (all three
meshes), 16 queries per face, first four discarded. Disjoint was false.

| Theme / face | Baseline median / min, ms | Checkpoint median / min, ms |
| --- | ---: | ---: |
| Light / front | .167 / .149 | .187 / .158 |
| Light / back | .213 / .157 | .190 / .163 |
| Dark / front | .160 / .143 | .149 / .138 |
| Dark / back | .169 / .163 | .142 / .097 |

The unchanged light repeat measured .294/.183 front and .321/.171 back.
These short, spaced queries are sensitive to clocks and other desktop work;
there is no consistent regression, but the light front's +.020 ms is not a
statistical proof of equivalence. Sustained paired measurements are preferable
for evaluating further changes.

### FXC

`WEBGL_debug_shaders` supplied both initial and final compiler-input HLSL.
`tools/windows-fxc.ps1` compiles the latter with the installed
`d3dcompiler_47.dll` (10.0.26100.9457), `main`, `ps_5_0`, flags 0 (/O1), and uses
`D3DDisassemble` to save listings. This calls FXC's APIs without installing the
SDK CLI. Compiler configuration is explicit; the browser build does not append
its flag list, so this is not a claim of byte-identical browser compile flags.

| Light variant | Offline /O1 | Instruction slots | `loop` instructions | DXBC bytes |
| --- | ---: | ---: | ---: | ---: |
| Baseline | 18.987 s | 5803 | 31 | 185116 |
| Shared tint jobs | 5.830 s | 4506 | 20 | 145312 |

Loops already survive in the baseline. The problem is not simply that every
loop is still unrolled: duplicated lighting at static call sites inflates the
optimized program. Sharing tint evaluation removes eleven emitted loops and
1297 instruction slots. Both offline builds succeeded on the first call, with
the same existing X4000 `f_brushed` warning. Browser logs are retained; no retry
diagnostic was observed, which does not prove that this browser logs all retries.

## Rejected experiment

Hoisting the shared diffuse `room(n, 1.0)` out of lettering reduced light compile
time to 11.069 s. Front matched, but back differed in six 8-bit channels by one
level. It was reverted rather than weakening the exact-hash requirement.

## Reproduction and limitations

Chrome 154.0.8037.58, Windows, RTX 5080, ANGLE D3D11, NVIDIA driver 32.0.16.1714.
Node 24.19; locked webgl dependencies installed with npm 10.9.3 `ci`.
`node variants/build.mjs` passes. `dist/` is generated, not committed.

```powershell
node variants/build.mjs
# Install Playwright externally, or point PLAYWRIGHT_MODULE at an existing installation.
node tools/windows-profile.cjs unique-light light dist C:\path\to\results
node tools/windows-profile.cjs unique-dark dark dist C:\path\to\results
./tools/windows-fxc.ps1 -InputHlsl C:\path\to\results\unique-light\shader-9.hlsl -OutputPrefix C:\path\to\results\unique-light\fxc-o1
```

Each run serves **local** files on an ephemeral loopback port, uses a fresh
Chrome profile and context, disables browser shader disk cache and HTTP cache,
blocks service workers, and forces `?render=full`. System/driver caches are not
globally deleted. Run browsers and offline compiles sequentially.

Theme is set before load; random seed 12345, reduced motion, DPR 1. The local
HTML response exposes `__cardRenderer` without enabling lab mode. The watchdog
is cancelled through its timer property, without changing shader source.
Shaders are retained until HLSL is exported, after compile timing. The harness
stops scheduled app frames and draws time=5, intro=1, introTime=10, four settling
draws per face, reduced=true. This is a deterministic Windows reference, not
the different-size Mac hashes from the handoff.

`result.json`, raw `.rgba` buffers, GLSL/HLSL, timestamped events, Chrome logs
and environment metadata are saved per uniquely named run. Program completion
is the first observed `KHR_parallel_shader_compile` status, with ~16 ms polling
granularity. This is compile/link-stage elapsed time, not CPU self-time.
The tested frames cover both home themes/faces; they do not exhaust every lab
combination, hover/focus state or orientation. Owner verification on Mac and
phones is still required before publishing.
