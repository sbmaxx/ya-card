# Server-Side Rendering Architecture

This document explains the server-side rendering (SSR) architecture used in the `ya-card` project.

## Purpose of Server-Side Rendering

Server-side rendering is used in this project to:

*   **Generate static HTML:**  Create a static HTML file (`index.html`) during the build process.
*   **Improve initial load performance:**  Deliver pre-rendered HTML to the browser, improving perceived performance and time to first contentful paint.
*   **SEO optimization:**  Ensure that search engine crawlers can easily index the content, as the initial HTML contains the fully rendered card.

## Files Involved in SSR

1.  **`src/node.js`**:  Entry point for the server-side rendering process.
2.  **`renderToStaticHtml.js`**:  Node.js script that orchestrates the SSR and HTML file generation.
3.  **`webpack.config.production.js`**:  Webpack configuration for building the server-side bundle (`node` bundle).

## `src/node.js` - Server-Side Entry Point

*   **Purpose:**  This file is the entry point for the Node.js environment to render the `Card` component to a static HTML string.
*   **Functionality:**
    *   Imports React and `ReactDOMServer` from `react-dom/server`.
    *   Imports the `Card` component (`src/Card/Card.jsx`).
    *   Imports data from `data.js`.
    *   Exports a `render()` function.
    *   The `render()` function uses `ReactDOMServer.renderToStaticMarkup(<CardReact {...Data}/>)` to render the `Card` component with data to a static HTML string.
    *   `renderToStaticMarkup` is used to generate a minimal HTML output without extra DOM attributes used by client-side React.

### Code Snippet (`src/node.js`):

```javascript
import React from 'react';
import ReactDOMServer from 'react-dom/server';
import CardReact from './Card/Card.jsx';
import Data from '../data.js';

export function render() {
    return ReactDOMServer.renderToStaticMarkup(<CardReact {...Data}/>);
}
```

## `renderToStaticHtml.js` - HTML Generation Script

*   **Purpose:**  This Node.js script combines the server-rendered HTML with the HTML template to create the final `index.html` file.
*   **Functionality:**
    *   Reads the HTML template from `./dist/template.html` (which is generated by Webpack during the build).
    *   Requires the compiled server-side bundle `./dist/node.js`.
    *   Calls the `render()` function from `./dist/node.js` to get the server-rendered HTML.
    *   Replaces the `<div id="root"></div>` placeholder in the template with the server-rendered HTML.
    *   Writes the final `index.html` file to `./dist/index.html`.

### Code Snippet (`renderToStaticHtml.js`):

```javascript
const fs = require('fs');
const template = fs.readFileSync('./dist/template.html', 'utf8');
const app = require('./dist/node.js');
fs.writeFileSync('./dist/index.html', template.replace('<div id="root"></div>', app.render()), 'utf8');
```

## Webpack Configuration for SSR

*   **`webpack.config.production.js`**:  The `server` configuration within this file is responsible for building the server-side bundle (`node` bundle).
*   **Target: `node`**:  The Webpack target is set to `node` to optimize the bundle for Node.js environment.
*   **Entry Point: `src/node.js`**:  `src/node.js` is defined as the entry point for the server bundle.
*   **Output: `libraryTarget: 'commonjs2'`**:  The output is configured as a CommonJS module, suitable for Node.js.
*   **Externals**:  `react` and `react-dom/server` are excluded as externals, assuming they are available in the Node.js environment.
